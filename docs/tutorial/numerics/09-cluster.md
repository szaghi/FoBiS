# 9. On a cluster

On a cluster the programs are built on the login node and run on compute nodes, through a scheduler. The commands
of this track take `--runner slurm`: each run becomes a Slurm job, and its results are read exactly as a local
run's, with the same probes and verdicts.

::: info Recorded on a cluster
This chapter ran on a Slurm 23.11 cluster with NVIDIA A30 GPUs and nvfortran 25.5 (NVIDIA HPC SDK), from the
project as chapter 8 left it. Its outputs were recorded there once and are not regenerated by the CI. The host
names, the Slurm account and the partition are replaced by generic ones.
:::

## The scheduler

Where to submit is a property of the machine, not of the project: it goes in the user configuration
(`~/.config/fobis/config.ini`), and a project can add to it in its fobos.

```ini
[scheduler]
kind        = slurm
partition   = gpu
account     = myproject
; run in every job before the program
setup       = module load nvhpc
; where MPI and GPU runs are refused
login_nodes = login*
; more #SBATCH lines
options     = --mem=32G
```

::: warning nsys and TMPDIR
With `TMPDIR` on a network file system, Nsight Systems records no CUDA or OpenACC event, without an error: FoBiS
runs it with `TMPDIR=/tmp`, local to the node. Found while recording this chapter.
:::

# 1. A local model

The last track puts a language model to work on `quad`: explaining failures, answering questions, writing tests,
reviewing changes, writing commit messages, resolving merge conflicts. In FoBiS a model never works alone. FoBiS
first computes the facts it can establish itself (where an error is, what a change touches, which module is
missing), gives the model only numbered sources, and checks what comes back: an answer must cite them, and code
must build and run.

The model runs on your machine (or your cluster), through llama.cpp: no account, no network after the download,
no code leaving the machine. The curated models:

<<< @/examples/output/6-ai/01/recommended.txt{console}

```bash
fobis llm runtime install     # the llama.cpp server, pinned and checksummed
fobis llm pull coder-7b       # the model, pinned to a commit and checksummed
fobis llm serve start         # optional: keep the server running between commands
```

::: info Recorded on a GPU node
The model outputs of this track were recorded with coder-7b (Qwen2.5-Coder 7B, 4-bit) on an NVIDIA A30 of a
cluster, in one Slurm job, and are not regenerated by the CI: a model's wording changes with its version and the
hardware. The commands and the deterministic outputs (contexts, facts) are generated and checked like the
other tracks. Paths under the cluster's home directory are shown as `~/fobis-dev`.
:::

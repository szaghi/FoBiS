# `new` command

Create a project: a module in src/, a program in app/, a test in test/, a fobos with debug and release modes and a [test] section, a .gitignore and a git repository (nothing committed). An existing file is never overwritten.

```bash
fobis new demo                  # ./demo: a module, a program, a test
fobis new kit --lib             # a library: no program, static and shared library modes
fobis new . --name my_tool      # fill this directory
fobis new demo --scaffold       # then fobis scaffold init --yes: CI, docs, release scripts
```

| File | What |
|------|------|
| `src/NAME.f90` | module `NAME` with one function (`mean`) |
| `app/main.f90` | program `main`, built as `build/<mode>/NAME` (not with `--lib`) |
| `test/test_NAME.f90` | a test program: `fobis test` runs it, a non-zero exit status is a failure |
| `fobos` | `[project]` (name, version 0.1.0, authors from `git config user.name`/`user.email`), modes `debug` (sources and tests, `build_profile = debug`) and `release` (`build_profile = release`; with `--lib` the static library, and a `shared` mode), `[test] test_dir = test` |
| `.gitignore` | `/build/`, `/.fobis_deps/`, `/.fobis/`, `/compile_commands.json` |

- `NAME` is the directory's name, or `--name`: it must be a Fortran name (a letter, then letters, digits or `_`).
- The modes use build profiles, so `--compiler intel_nextgen` (or any family) gets that compiler's flags.
- A git repository is initialised, with nothing committed, unless the directory is inside one already or
  `--no-git` is given.
- **Never overwrites.** When any of the files exists, nothing is written: the files are listed, exit 2.
- Exit codes: 0 created; 2 an invalid name or existing files; 1 `--scaffold` failed (the project is written).
- `--json`: `status`, `name`, `path`, `files`, `git` (and `scaffold`), or `status: error`, `error`, `conflicts`.

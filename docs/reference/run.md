# `run` command

Build a target and execute it in a single step.

```bash
fobis run [TARGET] [options] [-- BINARY_ARGS...]
```

If `TARGET` is omitted, the output name from the active fobos mode is used.
Arguments after `--` are forwarded verbatim to the binary.

## Options

| Option | Default | Description |
|---|---|---|
| `TARGET` | (fobos `output`) | Name of the target to build and run |
| `--no-build` | `False` | Skip the build step; execute the binary directly |
| `--dry-run` | `False` | Print the build and run commands without executing either |
| `--example NAME` | — | Run a `[[example.NAME]]` target from the fobos file |
| `--explain` | `False` | When the program fails, explain why (see [Explaining failures](/ai/explain#runtime-failures)); also passed to the build |
| `--explain-context` | `False` | Like `--explain`, but print what the model would receive instead of running it |
| `--launcher CMD` | mode key `launcher` | Start the program through `CMD` (see [launchers](#launchers)) |
| `--ranks N` | `1` | MPI ranks: replace `{ranks}` in the launcher; without a launcher, `mpirun -np {ranks}` |

## Launchers

A launcher is a command put in front of the program: an MPI launcher, a debugger, a memory checker.

```bash
fobis run --launcher "mpirun -np {ranks}" --ranks 4
fobis run --launcher "gdb --args" -- input.nml
fobis run --launcher "valgrind --error-exitcode=1"
fobis run --ranks 2                     # mpirun -np 2
```

- `{ranks}` is replaced by `--ranks` (1 when not given). `--ranks` without a launcher means `mpirun -np {ranks}`.
- A mode can keep its launcher: `launcher = mpirun -np {ranks}`. `--launcher` wins over it.
- The program's exit status is the launcher's (an MPI launcher returns its processes' failure).
- A launcher that is not on PATH stops `fobis run` before building (exit 2). On a login node declared in the
  [`[scheduler]` configuration](/advanced/scheduler), `--ranks` is refused (exit 2): run through Slurm instead.
- `--dry-run` prints the command with its launcher.

## fobos options

| Option | Description |
|---|---|
| `-f`, `--fobos` | Specify a fobos file with a different name or path |
| `--mode` | Select a fobos mode — tab-completable from the active fobos file |
| `--shadow NAME` | Rebuild the mode as a [shadow](/advanced/matrix#shadow-modes): `checks`, `sanitize`, `strict` (or `none`), in `.fobis/shadow/<mode>-<shadow>/` |

## Examples

```bash
# Build (if needed) and run the default target
fobis run

# Run with arguments forwarded to the binary
fobis run -- --input data.dat --nproc 8

# Run a named target
fobis run solver

# Skip rebuild, just run
fobis run --no-build

# Dry run: see what would be executed
fobis run --dry-run

# Run a named example
fobis run --example demo
```

## Exit codes

`fobis run` exits with the binary's own exit code; a binary killed by a signal gives 128 + the signal number,
as a shell reports it (139 for a segmentation fault, SIGSEGV). A non-zero exit from the build step causes an
immediate abort before execution.

::: tip Quick iteration
`fobis run` is equivalent to `fobis build && ./myapp`. Use it during
development to tighten the edit→compile→run loop without leaving the terminal.
:::

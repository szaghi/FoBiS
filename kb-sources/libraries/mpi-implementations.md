# MPI implementations: Open MPI, Intel MPI, MPICH family

What differs between MPI implementations in practice: launchers, environment, compiler wrappers, Fortran
modules. The semantics of MPI itself are in the mpi pack. "Measured" means observed with Open MPI 5.0.7 (built
with gfortran 14.2) and Intel MPI 2021.18 on one Linux machine with 16 processors.

## Identify the implementation

`mpirun --version` prints `mpirun (Open MPI) 5.0.7` or `Intel(R) MPI Library for Linux* OS, Version 2021.18.1
...` (measured); MPICH prints a `HYDRA build details` block. `fobis case run` and `fobis verify` record this line
in the provenance of every case run with ranks.

## More ranks than processors

Open MPI refuses to start more processes than there are slots (processors detected, without a hostfile or a
batch allocation). Measured, `mpirun -np 17` on 16 processors:

```
There are not enough slots available in the system to satisfy the 17
slots that were requested by the application:
```

`mpirun --oversubscribe -np 17` runs them. Intel MPI started 17 processes on the same machine without a flag
(measured). Oversubscribed ranks share cores, so their timings say nothing about the code. For FoBiS cases set
the launcher in the fobos, for example `[verification] launcher = mpirun --oversubscribe -np {ranks}`.

## Rank and size in the environment

Each launcher tells the processes who they are through environment variables, readable before `MPI_Init`
(for example to choose a GPU per rank). Measured:

| Implementation | rank | size | rank on the node |
|---|---|---|---|
| Open MPI 5 | `OMPI_COMM_WORLD_RANK` (also `PMIX_RANK`) | `OMPI_COMM_WORLD_SIZE` | `OMPI_COMM_WORLD_LOCAL_RANK` |
| Intel MPI | `PMI_RANK` | `PMI_SIZE` | `MPI_LOCALRANKID` |

Under Slurm's `srun` the variables are `SLURM_PROCID`, `SLURM_NTASKS` and `SLURM_LOCALID` (Slurm
documentation). Code that reads one implementation's variables silently gets nothing under another: read them
with a fallback, or use `MPI_Comm_split_type` with `MPI_COMM_TYPE_SHARED` after `MPI_Init` for the node-local
rank.

## Compiler wrappers

`mpif90`/`mpifort` call a Fortran compiler with the MPI include and library flags. Which compiler is not fixed
by the name:

- Open MPI: the compiler it was built with; `mpif90 --showme` prints the command (measured:
  `gfortran -I... -lmpi_usempif08 -lmpi_usempi_ignore_tkr -lmpi_mpifh -lmpi`).
- Intel MPI: `mpif90 -show` printed a gfortran command (with modules for gfortran 15.1 under
  `include/mpi/gfortran/15.1.0`), while `mpiifx -show` printed an ifx command (measured).

FoBiS modes with `mpi = True` compile with `mpif90` for gnu and nvfortran, `mpiifort` for `intel` and
`mpiifort -fc=ifx` for `intel_nextgen`; `fobis introspect --compiler` shows the command a mode runs. With Intel
MPI's `mpif90` a gnu mode gets gfortran, as intended; check the wrapper whenever several MPI installations are
on the PATH.

## Fortran modules belong to one compiler

The `mpi` and `mpi_f08` modules are compiled `.mod` files: they work only with the compiler (and module format)
that built them. Measured with an Open MPI built by gfortran 14.2: ifx stops with `error #7013: This module file
was not generated by any release of this compiler`, nvfortran with `NVFORTRAN-F-0004-Corrupt or Old Module
file`. Each compiler needs its own MPI build (or, for Intel MPI, its own module directory). The legacy
`include 'mpif.h'` avoids the module but loses argument checking, and is deprecated (mpi pack).

## GPU-aware MPI

Passing device buffers directly to MPI calls needs an MPI built with GPU support. For Open MPI:

```
ompi_info --parsable --all | grep opal_built_with_cuda_support:value
```

prints `...:value:false` for a build without it (measured). Without GPU support, a device address passed to MPI
is read as a host address: a crash or wrong data. With OpenACC, use `!$acc host_data use_device(buf)` only
when the MPI is GPU-aware; otherwise update the host copy before the call (hpc-practice pack).
